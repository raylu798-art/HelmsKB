# HelmsKB 助手单项移植

## 来源和范围

技术基线仍为 WeKnora v0.8.3（`3e22822c1d2397be730c458c7539d0eb8c113a24`）。独立助手首次在发布之后加入，因此品牌替换版本没有该入口。

按依赖顺序迁入下列上游提交的 `client/`、`config/`、`frontend/`、`internal/`、`migrations/` 及文档嵌入代码；保留上游版权和现有品牌：

| 提交 | 内容 |
| --- | --- |
| `383d265` | 持久化操作确认、提问与挂起/恢复，助手写操作所需依赖 |
| `234aa94` | 后续助手处理器依赖的 API DTO 与注解 |
| `687b178` | 内置助手、操作目录与页面上下文 |
| `7c9088d` | 内嵌产品文档查询 |
| `c40b33e` | 限制操作目录可调用的 API 区域 |
| `1b24132` | 助手检索不要求独立 Rerank 模型 |
| `a131efa` | 全局助手入口、面板和页面上下文 |
| `a37a1bc` | 工作空间操作支持 |
| `aaa1acc` | 文档批量整理操作 |
| `a730a41` | FAQ 操作支持 |
| `450b6ed1b781c36983c53d9d564ffe65a863b3e8` | 侧边栏、设置、权限等级和角色检查 |

没有迁入该范围内的 RRF 检索设置、Lite 列表布局、排行榜与站点发布工作流，也没有整体同步上游 main。

同时同步上述最终提交的 `docs/docs.go`、`docs/swagger.json` 与 `docs/swagger.yaml`。操作目录直接读取其中的 `x-agent` 注解，因此这些生成文件是运行依赖，必须与处理器、DTO 和权限投影保持一致。

HelmsKB 适配：助手名称、欢迎语和系统提示词使用自有品牌；兼容 ID、API、存储键及工具名保持不变；助手返回的文档引用使用本站 `/docs/`，仍能解析旧对话中的上游文档引用。原有 AnyDoc、DuckDB、BrowserSkill、解析器与存储功能在编译和运行打包时保留。

## 迁移与恢复

PostgreSQL 新增 `000119_agent_prompts` 和 `000120_tenant_assistant_config`：增加操作确认与挂起记录表、`messages.run_state` 和 `tenants.assistant_config`，不重写已有业务资料。SQLite 提供对应的 37、38 号迁移。

更新前停止写入，保存数据库、自有文件、队列和私有配置的完整备份，并记录原镜像。回退代码与恢复数据库分别处理；下降迁移会删除新增的助手配置与交互记录，不能当作无损恢复。应先停止新写入、保存更新后数据，再按该环境运行手册恢复备份与匹配的旧镜像。

## 验证

使用锁文件安装依赖。前端执行 `npm run check-i18n`、`npm run check:docs-links`、助手与交互回归测试、`npm run build:with-docs`。后端执行助手、操作目录、角色与所有权、挂起/恢复、处理器、迁移和文档查询的测试，再以 `anydoc` 标签构建完整服务。

验收路径：设置中出现助手 → 保存空间名称后刷新仍在 → 导航打开助手 → 选择对话模型 → 查询内嵌文档并显示本站引用。模型推理与写操作分别验证，不把页面显示正常当作真实调用成功。

运行部署与验收证据由各独立环境记录，不能将演示环境的端口、凭据或数据归入源码仓库的部署事实。
